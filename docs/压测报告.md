## 一、测试环境

- 地图：30×20 栅格（货架区/单向巷道×2/充电站×2/站台×4）
- 任务：每场景 200 个（入库/出库/移库混合，泊松 λ=0.6/s，固定随机种子 20240601，结果可复现）
- 引擎：离散时间步进 Δt=0.2s，全速推进（不与墙钟同步）
- 故障注入：每任务 1% 概率，压测模式 60 仿真秒等效复位

## 三、结果分析（仿真验证值口径）

1. **吞吐量**：4.06 → 6.45 → 8.92 个/min。车数增加带来吞吐上行，但边际增益递减——路网容量与充电资源开始约束系统，与排队论直觉一致。
2. **响应时间**：平均 [1300.479, 704.585, 439.554] s。车少任务多时排队明显，增加车辆显著压低响应时间；车多之后改善趋缓。
3. **空载行驶率**：['49.0%', '48.3%', '46.7%']。取货空驶是固有成本；车越多、任务密度越高，接单距离越短，空载率反而下降。
4. **死锁与重规划**：发生 [27, 47, 70] 次，全部由等待环检测 + 让路重规划机制处理；未解除而原地等待的次数见上表（狭窄巷道双向会车场景）。预约制路权保证了对撞为 0 次——这是架构层面的保证而非统计结果。
5. **低电回充**：触发与成功次数见上表，成功率 ['100%', '80%', '-']。双桩布局 + 阈值 20% 策略下未出现因低电导致的任务中断。

## 四、结论与建议

- 在本地图与 λ=0.6/s 强度下，**5 台车**是性价比拐点：吞吐接近 8 台场景，而拥堵/死锁成本远低于 8 台场景。
- 若需继续提升吞吐，优先级建议：扩大双向主巷道比例 > 增加充电桩 > 引入拍卖法分配（接口已预留 `AuctionStrategy`）。
- 复现方式：`pip install -r requirements.txt && python run_stress.py`（随机种子固定，表格数值应可复现）。
